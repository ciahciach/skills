# Excel Repo Contract Seed

Use this checklist to fill gaps in existing rules or seed a new local contract. Resolve concrete paths in the proposal. When a location or capability hasn't been agreed, record it as pending instead of treating it as configured. The [shared Excel contract](https://github.com/ciahciach/versuni-search-ecosystem/issues/63#issuecomment-7108392518) owns routing and runtime procedure; this document describes the local workflow, not another router.

## Local Paths and Authority

- Point to one location each for the workbook registry, reviewed editable source, generated inventory and existing tracker/knowledge rules (if configured). For a new repo, suggest per-workbook `excel/<id>/source/` and `excel/<id>/inventory/`; create them only when there is content. Don't add alternate locations to an existing repo.
- The repo owns approved managed logic and structure; the workbook owns business data and unmanaged objects. Register each workbook separately with its profile, managed scope, immutable base version/checksum and last approved sync point. With no workbook, there is nothing to register; an existing workbook needs separately approved onboarding and an initial reviewed export before establishing a sync point.
- Keep real workbook bases, checkpoints and required binary companions in access-controlled storage outside Git, pinned by immutable version and checksum. Keep `.frm` and its required emitted `.frx` paired. Keep business data, query results and secrets out of exports and evidence. Block publication if secrets are detected; a redacted preview is not import source.

## Managed Scope

- For Windows desktop Excel v1, identify one `.xlsx` or `.xlsm` per controlled import; no cross-workbook updates, silent format conversion or arbitrary reconstruction. Declare editable, inventory-only and out-of-contract objects. Omissions are not deletions.
- Edit explicitly targeted ordinary formulas and dynamic-array anchors, and existing names without changing scope. Preserve formula dialect, kind, exact pattern membership and exceptions; never write spill outputs or fill blank/constant holes. Stop if changed row positions make exceptions unsafe. Table rebuilds, calculated-column templates, legacy CSE arrays and what-if data tables are not managed edits.
- M edits are limited to existing queries and must preserve load destinations. Report load destinations, connection mappings and model presence without credentials. DAX, connections, PivotTables, validation and formatting are inventory-only. Load changes are a separate explicit Excel-side change on a copy, reviewed before registering a new base and sync point; any data access or refresh needs separate approval.
- Edit existing VBA modules in place, preserving document-module host identity, references and project topology. UserForm code and design require separate native validation on an `.xlsm` copy; HTML prototypes are not import artifacts. Block an affected operation if preservation cannot be verified, without disqualifying unrelated operations.

## Daily Workflow

1. **Export and review.** Use current text without launching Excel when it answers the request. For a new explicit export, use saved workbook state and the shared router. Verify freshness and scope; review Excel-side changes before accepting them as source. Review formula changes by exact target, dialect, kind and exceptions. Inventory edits never schedule workbook writes.
2. **Edit.** Modify only approved managed source; keep the intended diff separate from generated reports. Before any import, compare both the saved base and the proposed source to the last approved synchronization point. Stop on two-sided managed drift, even for apparently disjoint changes. Data-only drift is allowed only if preconditions still hold.
3. **Dry-run.** With no writes, identify the base/hash, target cells or objects, proposed changes, preservation checks and blockers. Use the shared router's classification and qualify the actual backend implementation, version, operation and workbook profile. Stop for an open/locked workbook, invalid base, unsafe targets, unverified preservation, or unavailable qualification. No automatic COM fallback. Approval of setup or dry-run is not approval to save.
4. **Save.** After approval and recheck, apply to a separate copy only. Standard import does not run macros, refresh queries or update links. Keep the original and approved sync point unchanged on failure or uncertainty. Never bypass VBA protection or IRM.
5. **Reopen and verify.** Reopen the saved copy, re-export and compare intended changes and preservation against the approved plan. Saving and same-session readback aren't proof of persistence. Record backend/version/profile and distinct results for dry-run, save, reopen/readback and any separately approved macro, compilation or refresh checks. Mark simulated or unperformed checks as such. Only verified, accepted results can advance the approved sync point.

## Power Query XLSX Pilot

To reproduce the [native acceptance run](https://github.com/ciahciach/skills/pull/46), run this from the skills repository on a logged-in Windows desktop with Excel, Python 3.14, pywin32 and Git available:

```powershell
py -3.14 -B -X utf8 scripts/excel-onboarding.py pq-pilot --desktop
```

`--desktop` authorizes Excel to create a new synthetic fixture and populate two tables once from literal-only queries: the target at `Odbior!B5:B6` and its neighbor at `Odbior!E5:E6`. Review the printed M change and plan, then enter its `planSha256` to authorize the no-op and Formula-only saves. Declining or closing input stops before either copy is saved. Only fixture creation refreshes anything; the copy saves and the independent read-only reopens never run macros, update links or refresh. Each native phase has a three-minute timeout.

The command prints the private attempt path under `%TEMP%\kilo`, and on success the disposable candidate path. `report.json` records the runtime, the phase results and hashes, and whether the fixture base and private sync stayed unchanged. A blocked attempt is not an accepted result; do not use any copy from it. No attempt publishes a workbook or advances sync, and no workbook or report belongs in Git. For manual acceptance, open the verified copy read-only: **`Odbior!B6` must still show `1`**. Close without saving or refreshing. The saved M contains `2`; the check does not test its execution.

The standalone `pq-plan`, `pq-prepare` and `pq-verify` commands below remain passive; the operator selects and qualifies the desktop step separately when using them. Run those commands with the target Git worktree as the current directory. See the [desktop pilot decision](https://github.com/ciahciach/skills/issues/39) and [runtime research](https://github.com/ciahciach/skills/issues/37).

1. Use a synthetic `.xlsx` with an existing worksheet-loaded query and a neighboring query, no Data Model, macros, external connections or refresh-on-open. Use numeric synthetic data and keep the result schema unchanged. `export --power-query` reads saved M into `power-query.json` and writes `power-query-inventory.json` separately. The inventory maps connection IDs to recognized queries, lists worksheet table/range destinations and reports Data Model presence. Unknown mappings block import. Review names, identifiers and constants before publication; nonempty inline M strings and comments block M export rather than producing redacted, non-importable M. Formula-only export does not parse M. Publish and accept a fresh initial sync for this fixture using the onboarding commands.
2. Make a proposed `power-query.json` at a separate worktree path. Review `git diff --no-index -- baseline/power-query.json proposed.json`. Keep the approved export immutable. Change exactly one existing expression, using one M expression rather than a section document. Inventory is never input. The preflight admits data-only differences it can prove (changed values in existing numeric or Boolean constant cells without a structural change); other differences block.
3. Select the route using the shared Excel contract. Qualify the exact implementation/version and Excel build on the logged-in Windows desktop before using the approval flags. Qualification needs separate authorization, isolation from external sources, control of opening effects, a no-op save/reopen, and a Formula-only round trip on disposable synthetic copies. Record what the route actually did. The CLI binds the operator's evidence reference to the plan, not the truth of the attestation. No evidence means stop; don't infer it from the synthetic CLI tests.
4. Run `pq-plan baseline proposed.json attempt --qualified-route <version-and-evidence-ref> --store <private-dir>`. Review its base, query, candidate, expected checks and SHA-256. After explicit approval run the same arguments with `pq-prepare` and `--approved-plan <plan-sha256>`. It rechecks inputs and creates `workbook.xlsx` and a plan receipt under `<private-dir>/candidates/attempt/`.
5. In the qualified route, open **only** that disposable copy with links, macros and refresh disabled. Confirm the Excel session is writable and AutoSave is off. Assign the approved expression to the existing query's `WorkbookQuery.Formula` and save once. For an explicitly qualified ExcelMcp/Excel CLI implementation, the equivalent update is `powerquery.update` with the exact `queryName`, approved `mCode` and explicit `refresh: false`. Do not use Power Query Editor preview, evaluate, load-to, create or Refresh All as substitutes. Close, independently reopen the saved copy read-only in a fresh session, confirm the Formula and destination wiring, and close without saving. Record the exact saved SHA-256 used for that readback.
6. Run the same approved arguments with `pq-verify`, `--reopened-sha256 <candidate-sha256>`, `--save-evidence <save-ref>` and `--reopen-evidence <reopen-ref>`. It compares all saved M, the load inventory and the remaining package parts. It allows the normal core modified timestamp and the mashup's user-bound signature and telemetry ID to vary. In `xl/workbook.xml`, it permits only a local saved path updated to the exact candidate directory and a revision document ID changing either within the observed `13_ncr:1_{GUID}` format or from `8_{GUID}` to `13_ncr:1_{GUID}` on the first save of a copy. It records which of those fields changed without exposing their values. See Microsoft's descriptions of [absolute path](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/9387c5cc-1378-4b52-a6c4-4ef7c7d3bff2) and [revision metadata](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-xlsx/7fc8862a-63f2-4263-8334-b9e72b480c8e). Any other unverified difference blocks. Evidence is written privately to `<private-dir>/review/attempt/`, distinguishing passive checks from the operator attestations. It does not publish, accept the copy or advance sync. On any failure, discard the attempt and start from the unchanged original with a new label. No M execution or refreshed data is verified by this procedure.

## Manual Load Change

1. Start from an approved synthetic XLSX with a saved M and load inventory. Identify one worksheet-loaded query, its current table and the intended new location. The verifier covers only a horizontal move of that same table to an empty, disjoint range of the same size. Connection-only and Data Model transitions, sheet changes and automatic reconciliation are out of scope. The portable fixture simulates `Loaded Query` moving from `Model!D1:D2` to `Model!F1:F2`; it is not desktop qualification.
2. Get explicit authorization for the exact move and qualify that operation for the Excel implementation/build and workbook profile. Standard M pilot qualification does not cover it. Make a separate Git-ignored working copy in access-controlled storage within the worktree. On the copy only, perform the manual move in Excel, save, close, then independently reopen read-only and inspect the saved destination. Review any workbook logic that refers to the old location. If opening, moving or verifying requires data access or refresh (including an automatic refresh), stop and request separate authorization before proceeding. Close without saving after the reopen and record the exact saved checksum. Neither CLI command opens Excel or evaluates any query.
3. Run the passive review shown below from the worktree. Compare the intended move with `change`, `before` and `after`. Compare all workbook artifacts privately and record the independent save/reopen evidence. The verifier checks unchanged connections, M and adjacent package parts, and compares the moved table and cells with their prior contents, including unchanged cells outside the move. Extras it cannot verify block acceptance. The inventory describes what happened; it is never input to an import.

```powershell
python -B -X utf8 <script> pq-load-review baseline moved.xlsx new-baseline --query "Loaded Query" --to F1:F2 --qualified-route <version-and-evidence-ref> --save-evidence <save-ref> --reopen-evidence <reopen-ref> --reopened-sha256 <saved-sha256> --store <private-dir>
```

4. If the reviewer explicitly accepts, rerun with `pq-load-accept` and `--accepted <reviewSha256>`. It recomputes the review, retains the exact saved copy by checksum, publishes a new text export and advances the synchronization point to the copy. The private `<reviewSha256>.load-review.json` in `versions/` distinguishes operator attestations from passive checks. A changed checksum, rejection or failed verification leaves the original and prior approved sync in place. On rejection, do not run acceptance. If interrupted, inspect `sync.json` before retrying: unreferenced output is not an approved baseline. Clear a stale `load-accept.lock` only after confirming no acceptance is running, verifying which baseline `sync.json` points to, and restoring the pointer's read-only status if necessary. Never overwrite the approved export or use a partial attempt as input.
