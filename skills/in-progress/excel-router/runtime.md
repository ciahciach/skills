# Runtime and persistence controls

Use an identifiable owned Excel instance and an isolated working copy for application tests or development. Never attach to the user's Excel. Work on an original only with separately explicit scope. Check the target/path and owner lock file before opening; if locked, stop. Use `Visible=False` by default; if necessary for diagnostics, authentication or scoped visual evidence, record the reason and protect confidential content. Do not force foreground or automate arbitrary dialogs.

Before each programmatic `Open`, capture `AutomationSecurity`, set `ForceDisable` immediately around `Open`, and restore the captured value even on error. Pass `UpdateLinks=0` to that call. Neither prevents all XLM, calculation, refresh-on-open, connections or background refresh. Identify and control these effects or stop if outside scope. Disable events where required and restore actual prior settings at the right boundary; restoring security does not run skipped startup macros. No Trust Center changes. Macro execution and refresh are separate effects that must be in scope.

For qualification, record the settings and arguments immediately before `Open`, restoration after successful and failed `Open` checks, and separate results for events, XLM and refresh. Mark untested checks `NOT_RUN`; successful readback does not prove opening controls.

Before editing, read AutoSave and warnings and decide whether the actual copy/location and save scope permit continuing. This is a decision control, not a guarantee; if unknown, do not promise that nothing was saved. Account for shutdown saves and close only an owned session with the intended save decision. Discard cannot undo earlier AutoSave.

Use bounded waits and at most three justified attempts, or a stricter host/project limit. Timeout can leave synchronous COM running or the outcome unknown. Account for the owned session/process before proceeding. Do not blindly replay writes, kill user processes or claim rollback. Preserve workbook structures, protection, format and modern functions; no unconditional unmerge, reconstruction, VBA reference changes or downgrade for a validator.

After authorized save, independently reopen the actual saved copy for readback without saving it again. In-session readback is an intermediate check. Qualification of a new application writer needs separate no-op preservation and targeted edit on copies, invariant checks of important parts and behavior, and independent reopen/readback. A read-only route instead needs evidence of the read and fully scoped opening effects, not a test save. For VBA, distinguish import, behavior and compilation; absent a trustworthy compile oracle, report `NOT_RUN`/`NOT_VERIFIED`. A macro assertion or `IsDirty` cannot prove full compilation.
